# Front-end developer report 3: liquid-glass redesign, quick search, Portfolio tabs

## What changed

## Test root cause (dist replaced by an old page)
- I could **not reproduce a deterministic cause**. Over about 14 full `npm run build && npm test` runs here, dist stayed correct (11865 bytes, 4 projects), and a watcher polling `dist/projects/index.html` every 0.2s saw writes only from the real builds. I also found no test that builds into the real dist: `qc-build-edge` builds in `os.tmpdir()` copies; every other file only reads.
- **One anomaly:** in one run here (about 20:05) the page was 3669 bytes after the tests and one test failed; I did not capture which, and it did not recur. That page size matches the old committed (five-project) page, which my tests cannot produce. This points to another process building the committed (old) source into the same `dist/` while the suite ran (for example a second verification run or agent in the same folder), not to a test.
- Fixes on the test side (cheap hardening, so any real leak is contained and named): the throwaway builds now run with `--root <copy> --outDir <copy>/dist`, with all `npm_*` and `INIT_CWD` variables removed from their environment; a final test in `qc-build-edge.test.mjs` fails if the real `dist/projects/index.html` changed while they ran; `site.test.mjs` gets a freshness test that fails with "dist is older than src/ or public/, run npm run build" if dist is stale. If it still happens on your machine, the failing test names will now show whether a leak (new last test) or a stale/foreign build (freshness test) is the cause. Please run the suite when no other build or agent is working in the folder.
